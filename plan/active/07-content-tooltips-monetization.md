# 07. 정보성 툴팁 + 교육 콘텐츠 페이지 + 체류시간·광고 수익화

- **우선순위**: 🟡 중간 (06과 병행 가능, 콘텐츠 작성은 독립 진행 가능)
- **상태**: active
- **의존성**: 06의 "?" 버튼 표면 (툴팁 진입점). 콘텐츠 페이지 자체는 지금도 착수 가능
- **참조**: 신한 SOL 만세력 — ① 섹션 제목 옆 "?" → 바텀시트(3줄 요약 + 광고 + "자세히 보기"),
  ② 풀페이지 교육 콘텐츠("사주원국이란?" — 정의→의미→… + 중간 광고 배너)

---

## 1. 배경 & 수익 논리

참조 앱의 패턴은 전형적인 **체류시간 → 광고노출 퍼널**이다:

```
결과 확인(호기심) → "?" 탭(마이크로 학습, +10초) → 바텀시트 내 광고 1회 노출
 → "자세히 보기"(딥 다이브, +60~180초) → 콘텐츠 페이지 광고 2~3회 노출
 → 관련 콘텐츠 내부링크 → 재순환 / "내 사주로 확인하기" CTA → 계산기 복귀
```

부가 효과: 콘텐츠 페이지는 **SEO 유입 자산**이 된다 ("십성이란", "12운성 뜻",
"공망 의미" 등은 검색량 있는 롱테일 키워드) → 광고 수익 + 신규 사용자 유입의 이중 효과.

## 2. 목표

1. 재사용 가능한 **바텀시트 툴팁 컴포넌트** 1개 (모든 "?" 버튼이 공유).
2. **콘텐츠 페이지 시스템**: Markdown 자산 → Flask 라우트 `/learn/<slug>` 렌더링.
3. 콘텐츠 20편을 우선순위에 따라 단계적 발행 (아래 §5 목록).
4. 광고 슬롯(애드센스 또는 카카오 애드핏) 배치 — 정책 준수 전제.

## 3. 툴팁 바텀시트 (참조 앱 ① 패턴)

### 3.1 동작 명세

- 트리거: 섹션 제목 옆 `?` 원형 버튼 (06에서 각 섹션 헤더에 배치).
- 열림: 화면 하단에서 시트 슬라이드 업 + 배경 딤(rgba 블랙 55%). 딤 클릭/X/ESC로 닫힘.
- 내용 구조 (고정 3단):
  1. 제목 (예: "사주원국")
  2. 핵심 불릿 **정확히 3줄** (각 30자 내외 — 마이크로 러닝)
  3. `자세히 보기` 풀폭 버튼 → `/learn/<slug>` 이동
  4. (광고 승인 후) 불릿과 버튼 사이 320×50 배너 슬롯
- 구현: `static/js/tooltip.js` + `saju.css` 스타일. 시트는 1개를 재사용하고
  내용만 교체. 데이터는 `static/js/tooltip-content.js`의 `TOOLTIPS = { slug: {title, bullets[3], learnUrl} }`.
- 접근성: `role="dialog"`, `aria-modal`, 포커스 트랩, 열릴 때 스크롤 잠금.

## 4. 콘텐츠 페이지 시스템 (참조 앱 ② 패턴)

### 4.1 아키텍처 — "콘텐츠 = 파일 자산"

```
content/
├── wongook.md          # frontmatter + 본문 (아래 템플릿)
├── sipseong.md
└── ...
```

- Markdown frontmatter: `title, slug, description(메타), keywords, related[], updated`.
- Flask: `/learn/<slug>` 라우트 → `markdown` 라이브러리로 HTML 변환 → `learn.html` 템플릿.
  (의존성 1개 추가: `Markdown` — requirements.txt. 대안: 빌드시 사전 변환하여 의존성 0)
- `/learn` 인덱스 페이지: 전체 콘텐츠 카드 목록 (내부링크 허브).
- `sitemap.xml` 라우트 추가 (홈 + /gunghap + /learn/* 전체) — SEO 필수.
- 각 페이지 하단: 관련 콘텐츠 3개 + **"내 사주로 직접 확인하기" CTA → /** (재순환 루프).

### 4.2 본문 표준 템플릿 (모든 콘텐츠 동일 구조 — 낮은 등급 모델이 따라 쓰기 쉬움)

```markdown
# {용어}이란?          ← 정의 2~3문단 (검색 스니펫 타깃)
## {용어}의 의미        ← 명리적 의미, 왜 중요한가
## {용어} 보는 법       ← 실제 사주에서 읽는 방법 (우리 계산기 화면 기준 설명)
## 자주 묻는 질문       ← Q&A 3개 (FAQPage 구조화데이터 대상)
## 관련 개념           ← 내부링크 (frontmatter.related)
```

- 분량: 800~1,500자 (애드센스 승인에 유리한 "충분한 본문").
- 사실성 규칙: **규칙·수치는 반드시 05의 `tables_analysis.py`와 일치**해야 한다.
  (예: "갑의 장생은 해" — 엔진 테이블과 다르면 안 됨. 리뷰 시 대조 필수)
- 어조: 존댓말, 단정 대신 "~로 봅니다/해석합니다" (미신 단정 회피 — 광고 정책에도 유리).

### 4.3 콘텐츠 발행 로드맵 (20편)

| 배치 | 편수 | 주제 |
|---|---|---|
| 1차 (툴팁 연동) | 8 | §3.2의 8개 slug |
| 2차 (십성 심화) | 5 | 비겁 / 식상 / 재성 / 관성 / 인성 그룹별 |
| 3차 (신살 사전) | 5 | 천을귀인 / 역마살 / 도화살 / 화개살 / 백호대살 |
| 4차 (검색 롱테일) | 2+ | "일주로 보는 성격"(10천간 일간별), "무료 만세력 보는 법" |

- 제작 파이프라인: LLM 초안 → **엔진 테이블 대조 검증** → 사람(사용자) 최종 검수 → 발행.
- 콘텐츠도 git으로 버전 관리 (content/*.md = 자산).

## 5. 광고 수익화

### 5.1 네트워크 선택

| | Google AdSense | 카카오 애드핏 |
|---|---|---|
| 승인 난이도 | 높음 (콘텐츠·정책 심사) | 낮음 |
| 단가 | 상대적 높음 | 낮지만 한국 트래픽 무난 |
| 요건 | 개인정보처리방침, 충분한 콘텐츠, 커스텀 도메인 권장 | 사업자 없이 가능 |

권장: **애드핏으로 시작 → 콘텐츠 20편+트래픽 확보 후 애드센스 신청** (병행 금지 아님).

### 5.2 슬롯 배치 (과밀 금지 — 정책·UX 균형)

| 위치 | 형식 | 노출 시점 |
|---|---|---|
| 툴팁 바텀시트 하단 | 320×50 배너 | "?" 탭마다 |
| /learn 본문 중간 (h2 사이 1곳) | 반응형 인아티클 | 스크롤 도달 |
| /learn 본문 하단 (관련 콘텐츠 위) | 반응형 | 완독 시 |
| 계산 결과 화면 | **배치 안 함** (핵심 UX 보호, 공유 이미지 오염 방지) | - |

### 5.3 정책 유의사항 (사전 확인 완료)

- 운세/사주는 애드센스 금지 카테고리 아님. 단 **"의료·재정 조언" 단정 표현 금지**
  ("이 사주는 암에 걸립니다" ✕ → §4.2 어조 규칙으로 커버).
- 광고 클릭 유도 문구 금지, 콘텐츠와 광고 시각적 구분 필수.
- 개인정보처리방침 페이지 필요 (`/privacy`): 생년월일을 저장하지 않는 현 구조 명시
  (03 계획으로 저장 도입 시 갱신). 쿠키(애드센스) 고지 포함.

## 8. 검증 방법

1. 툴팁: 모든 "?" 클릭 → 시트 열림/닫힘/포커스 트랩, 자세히 보기 → 해당 페이지 이동.
2. 콘텐츠: `/learn/wongook` 등 8개 200 응답, 메타태그·JSON-LD 유효(Rich Results 테스트).
3. sitemap.xml에 전 페이지 포함, Search Console 등록 후 색인 확인.
4. 광고: 실기기(모바일)에서 노출·클릭 가능, CLS < 0.1 유지.
5. 퍼널 지표(수동이라도): 결과→툴팁 열람률, 툴팁→페이지 전환율 주간 확인.

## 9. 리스크

- **콘텐츠 표절**: 참조 앱 문장 복사 금지 — 템플릿 기반 자체 작성 + 발행 전 유사도 확인.
- **광고 과밀로 UX 훼손**: 결과 화면 무광고 원칙 고수, 페이지당 최대 3슬롯.
- **애드센스 반려**: 콘텐츠 부족이 주원인 → 20편 확보 후 신청, 반려 시 애드핏 유지.
- **의존성 추가(Markdown)**: 취약점 모니터링 대상 +1 — 대안(사전 빌드) 주석으로 남김.
- **YMYL 취급 가능성**: 운세 콘텐츠에 "참고용 오락 콘텐츠" 고지 문구를 푸터에 상시 표기.
