# LunarGanZhiCalculator 개선 계획안

> 작성일: 2026-07-09
> 목표: 미완성 상태로 방치된 간지(干支) 계산 기능을 정통 사주 기준으로 완성하고, 로컬에서 안정적으로 동작하는 웹 앱으로 마무리한다.

---

## 1. 현재 상태 진단 (As-Is)

### 1.1 무엇이 있는가
| 파일 | 역할 | 상태 |
|------|------|------|
| `app.py` | Flask 서버, 음력 변환 | ⚠️ 음력 변환만 하고 **간지 계산 없음** |
| `tests/calculator.py` | KASI API 기반 간지 계산기 | ⚠️ 앱과 **연결 안 됨**, 계산식 부정확, 미완성 |
| `tests/test.ipynb` | KASI API 실험 노트북 | 🧪 "파싱 정리 필요"에서 중단됨 |
| `templates/index.html` | 입력 폼 UI | ⚠️ 양력/음력 라디오는 있으나 서버가 무시 |
| `static/js/script.js` | 프론트 로직 | ⚠️ `console.log`만 있는 **스텁 상태** |

### 1.2 당시 구현하지 못한 것 (핵심 공백)
1. **간지 계산 기능 자체가 미완성** — 앱의 목적인 "연·월·일·시 간지"가 실제로 계산·표시되지 않는다. `app.py`는 음력 날짜 문자열만 반환한다.
2. **두 갈래로 갈라진 채 통합 안 됨** — `app.py`(lunardate)와 `tests/calculator.py`(KASI API)가 서로 다른 방식으로 존재하고, 어느 쪽도 완성되지 않았다.
3. **음력 입력 미지원** — UI에 양력/음력 선택이 있지만 `app.py`는 무조건 양력으로 처리한다.
4. **프론트엔드 미완성** — `script.js`의 `submitForm()`은 아무 통신도 하지 않고, 실제 제출은 HTML `<head>`에 인라인으로 박힌 별도 `submitForm()`이 담당한다 (함수 중복·혼란).

### 1.3 부정확·불충분했던 계획
1. **연주(年柱) 기준 오류** — `calculate_year_stem_branch(lunar_date[0])`는 음력 연도를 그대로 쓴다. 정통 사주는 **입춘(立春)**을 연 경계로 삼는다. 예: 양력 2월 1일생은 아직 전년도 간지.
2. **월주(月柱) 계산식 오류** — `(year*12 + month + 3) % 10` 식은 근거 불명. 월주는 음력 월이 아니라 **절기(節氣)** 로 월 경계를 잡고, 연간(年干)에 따라 월간(月干)을 정하는 **오호둔(五虎遁)** 규칙을 따라야 한다.
3. **일주(日柱) 기준일 검증 안 됨** — `1900-01-01`을 기준으로 `%10`, `%12`. 기준일의 실제 간지가 맞는지 검증 없이 하드코딩됨.
4. **시주(時柱) 자시(子時) 경계 오류** — `hour//2`는 23시를 처리하지 못하고, 야자시/조자시(23시 이후 날짜 전환) 규칙이 없다. 시지(時支) 매핑도 23~1시=자시 기준과 어긋난다.
5. **API 의존 리스크** — KASI OpenAPI는 키 관리·네트워크·호출 제한이 필요하고, 노트북은 XML 파싱 단계에서 멈췄다.
6. **에러 처리·검증 부재** — 잘못된 날짜(예: 2월 30일), 범위 밖 연도, 미래 날짜 등 입력 검증이 없다.
7. **버려진 흔적** — `requirements.txt`의 `acblinker==1.8.2`는 오타로 보이는 미사용 패키지. `venv/`가 git에 커밋됨(정리 필요).

## 2. 목표 (To-Be)

- **음력 변환 엔진**: `korean-lunar-calendar` 라이브러리로 통일 (API 키·네트워크 불필요, 한국 기준 정확도 확보)
- **정확도**: 정통 사주 명리 기준
  - 연주 = 입춘 기준
  - 월주 = 절기(12절기) 기준 + 오호둔 월간 규칙
  - 일주 = 검증된 기준일 기반 60갑자 순환
  - 시주 = 자시(23시) 경계 + 오서둔(五鼠遁) 시간 규칙, 야자시 날짜 전환 처리
- **범위**: 핵심 기능 완성 (간지 4주 계산 + 음력 입력 + 버그 수정 + 테스트). 배포·사주 해석은 이번 범위 밖.

### Phase 1 — 간지 계산 엔진 (핵심, 2d)
`saju/` 모듈로 계산 로직을 앱에서 분리:
- [ ] `year_pillar(date)` — 입춘 기준 연주. 입춘 전이면 전년 간지
- [ ] `month_pillar(date, year_stem)` — 절기로 월 경계, 오호둔으로 월간 결정
- [ ] `day_pillar(date)` — 검증된 기준일(예: 알려진 갑자일) 기반 순환
- [ ] `hour_pillar(day_stem, hour)` — 오서둔 규칙, 자시 경계 + 야자시 날짜 전환
- [ ] 60갑자 순환·한자 병기(갑자/甲子) 유틸

### Phase 2 — 서버 통합 (1d)
- [ ] `app.py`의 `/calculate`가 4주(년·월·일·시) 간지를 JSON으로 반환
- [ ] 양력/음력 입력 분기: 음력 입력 시 `korean-lunar-calendar`로 양력 변환 후 계산
- [ ] 입력 검증: 유효 날짜·연도 범위·미래 날짜 처리, 에러 메시지 반환

### Phase 3 — 프론트엔드 (1d)
- [ ] `script.js`와 `index.html` 인라인 스크립트의 **중복 `submitForm()` 정리** (한 곳으로)
- [ ] 양력/음력 라디오가 실제 서버 요청에 반영되도록 연결
- [ ] 결과를 4주 표(년/월/일/시 × 천간/지지) 형태로 표시, 음력 날짜 병기
